# 멀티플레이 규칙

혼자 하기 규칙(README §1)은 그대로 두고, 여럿이 한 방에서 겨룰 때 달라지는 것만 적습니다.
2026-10-26 사용자와 정한 결정은 **[결정]**, 아직 확인하지 않은 기본값은 **[기본값]**으로 표시합니다.
구현: `js/multi.js`(진행·화면), `js/net.js`(통신). 같은 날 1차 구현했습니다(§4).

## 1. 정한 것

* **[결정] 동시 출제.** 방의 모두가 같은 국기 10개를 같은 순서·같은 타이머로 풉니다. 문제는 방장 브라우저가 한 번 뽑아 모두에게 보냅니다.
* **[결정] 출제 방식은 방장이 대기실에서 고른다** (2026-10-26). 이름 + 위치 / 이름만 / 위치만 세 갈래 중 하나(방 상태 `room.mode` = `both`·`name`·`place`)이고 모두에게 같게 적용됩니다. 참가자 화면에도 같은 선택지가 보이지만 누를 수 없습니다. 만점은 2,000 / 1,000 / 1,000점이고, 최종 순위의 맞힌 수도 푼 단계만 보여 줍니다.
* **[결정] 판이 끝나면 방장이 고른다.** 「다시 하기」는 같은 방식으로 바로 시작하고, 「대기실로」는 대기실로 돌아가 방식을 바꿀 수 있습니다.
* **[결정] 이름은 각자 입력창.** 남의 답은 보이지 않고, 누가 맞혔는지만 점수판에 「정답!」으로 뜹니다. 늦게 맞혀도 혼자 하기와 같은 시간 곡선으로 점수를 받습니다(바로 100 → 시간 끝 20).
* **[결정] 넘어가기 = 전원 답 또는 시간 끝.** 단계(이름 15초, 지도 25초)마다 접속 중인 사람이 모두 답했거나 제한 시간이 끝나면 다음으로 넘어갑니다.
* **[결정] 문제 결과 화면에 모두가 누른 위치.** 지도 단계가 끝나면 정답 나라를 칠하고, 참가자마다 누른 자리를 닉네임 핀으로 찍습니다. 지도 단계 중에는 남의 핀을 보여 주지 않습니다.

### 1.1 지도 누르기 (모바일 대책)

멀티에서는 점수가 걸려 있습니다. 혼자 하기처럼 손가락을 떼는 순간 바로 제출하면, 확대하다 잘못 눌리거나 손가락에 가려 다른 나라를 누른 실수가 그대로 점수가 됩니다.

* **[결정] 핀 놓고 확정.** 누르면 핀만 꽂히고, 다시 누르면 핀이 옮겨집니다. 크게 뜨는 「확정」 버튼을 눌러야 제출됩니다. 끌기·두 손가락 확대는 지금처럼 핀을 건드리지 않습니다(8px 넘게 움직이면 끌기).
  * 점수 시각은 **마지막으로 핀을 놓은 때**입니다. 확정 버튼을 늦게 눌러도 손해가 없어서 확정 전에 한 번 더 확인할 수 있습니다.
  * 시간이 끝나면 놓인 핀이 자동 제출되고, 핀이 없으면 무응답입니다.
  * 「전원 답」 판정은 확정 기준입니다.
* **[결정] 지도 전체 화면.** 좁은 화면(폭 820px 이하)의 지도 단계에서는 문제 카드를 한 줄(국기 작게, 나라 이름)로 접고 지도가 나머지 화면을 채웁니다. 점수판은 맨 위 한 줄 칩으로 접어 계속 보입니다(2026-10-26 개편 전에는 지도 아래에 두고 핀을 놓는 동안 숨겼음). 혼자 하기에도 같은 배치를 씁니다.
* **[결정] 지도 단계 25초.** 혼자 하기의 20초보다 5초 늘립니다. 모두 똑같이 적용하고, 점수 곡선(바로 100 → 시간 끝 20)도 25초 기준으로 계산합니다. 혼자 하기에도 맞출지는 나중에 정합니다.
* 이미 있는 완화책은 그대로 둡니다: 경계 바깥 24px·400km 안은 정답, 틀려도 2,000km 안이면 최대 40점.

## 2. 한 문제의 흐름

1. 이름 단계 (15초): 국기를 보고 각자 이름을 씁니다.
2. 이름 결과 (2.5초): 정답 나라 이름과 맞힌 사람을 보여 줍니다. **[기본값]**
3. 지도 단계 (25초): 지도가 전체 화면으로 커지고, 각자 핀을 놓은 뒤 「확정」을 누릅니다(§1.1).
4. 지도 결과 (6초): 정답 나라, 모두의 핀(닉네임)과 거리(km), 이번 문제 점수. **[기본값]**
5. 다음 문제. 10문제가 끝나면 최종 순위와 내 문제별 결과(각자 브라우저가 문제 결과가 나올 때마다 자기 답을 적어 둔 것).

출제 방식에 따라 건너뛰는 단계:

| 방식 | 한 문제 |
|---|---|
| 이름 + 위치 | 1 → 2 → 3 → 4 |
| 이름만 | 1 → 2. 이름 결과를 4초로 늘리고 지도에 정답 나라를 칠해 보여 줍니다 |
| 위치만 | 3 → 4. 국기와 나라 이름을 함께 보여 줍니다 |

### 2.1 화면 (2026-10-26 개편)

* 처음 화면은 「싱글」·「멀티」 탭으로 나눴습니다. 폰에서도 한 화면에 들어옵니다. 문구는 웹 멀티게임(사과게임 등)처럼 짧고 건조하게 씁니다: 방 생성·방 입장·입장·게임 시작·방장 시작 대기 중·다시 하기·대기실로·메인으로.
* 대기실: 방 코드와 「초대 링크」(폰은 공유 시트, 데스크톱은 링크 복사) → 출제 방식 → 참가자(최대 12명) → 게임 시작(방장) 또는 「방장 시작 대기 중」(참가자).
* 게임 중: 타이머 막대 옆에 남은 초. 위 줄 「나가기」는 3초 안에 두 번 눌러야 나갑니다(방장이 나가면 방이 닫힘). 폰에서는 점수판을 맨 위 한 줄 칩(옆으로 밀기)으로 두어 지도를 누르는 동안에도 보입니다.

## 3. 아직 정하지 않은 것 (기본값으로 시작)

| 항목 | 기본값 | 이유 |
|---|---|---|
| 방 인원 | 최대 12명 | 여행 인원 8명에 여유 |
| 판 시작 | 방장이 「시작」을 누름 | 다 모일 때까지 기다림 |
| 중간 입장 | 다음 판부터 참가, 그 전엔 구경 | 점수가 0부터라 불공평 |
| 접속 끊김 | 10초 넘게 소식(3초마다 보내는 신호)이 없으면 「전원 답」 판정에서 빼고 점수판에 「연결 끊김」. 같은 탭에서 다시 들어오면 점수를 이어서 | 한 사람 때문에 매번 시간 끝까지 기다리지 않음 |
| 정답 판정 | **지금은 각자 브라우저가 판정**해 결과(맞음·거리·점수·핀 좌표)를 방장에게 보냄. Cloudflare로 옮기면 서버가 판정 | 지도 판정에 각자의 확대 상태가 필요함. 친구끼리라 결과를 믿음 |
| 시간 기준 | 방장이 단계 끝 시각을 정하고 남은 시간을 내려 줌. 시간 끝 뒤 1.5초는 늦게 오는 답을 기다림 | 폰마다 시계가 달라도 같은 타이머 |
| 방장이 나감 | 방이 닫히고 모두 처음 화면으로. 방장 신호가 15초 끊겨도 같음 | 방장 브라우저가 곧 서버라서 |
| 최종 순위 | 총점 순, 같으면 이름+위치 맞힌 수 | |

## 4. 통신

### 4.1 지금 (2026-10-26, abstract_quiz 방식)

서버 없이 **방장 브라우저가 서버 역할**을 합니다. `js/net.js`는 abstract_quiz의 것을 그대로 가져와 토픽 이름(`fmq_v1_net/<방코드>/…`)만 바꿨습니다.

* 중계: 공개 MQTT 브로커(`wss://broker.emqx.io:8084/mqtt`) + 같은 기기 탭 채널(BroadcastChannel) + PeerJS(WebRTC). 같은 메시지가 여러 길로 와도 메시지 ID로 한 번만 처리합니다.
* 방장 → 모두: `STATE_SYNC`(방 상태 전체). 바뀔 때마다, 그리고 3초마다 다시 보냅니다. 지도 단계 중에는 남의 핀 좌표를 빼고 「확정함」만 보냅니다.
* 참가자 → 방장: `NAME`·`PLACE`(내 판정 결과), `PING`(3초마다), `LEAVE`.
* 한계: 공개 브로커라 인증이 없습니다. 방 코드(5자)를 아는 사람은 토픽을 엿보거나 끼어들 수 있고(비밀번호는 입장만 막음), 브로커가 느려지거나 멈춰도 손쓸 수 없습니다. 방장이 나가면 방이 끝납니다.

### 4.2 나중 (Cloudflare)

Cloudflare Workers + Durable Objects로 방 하나를 객체 하나로 둡니다. 화면은 지금처럼 GitHub Pages에 둡니다.
`js/engine.js`가 node와 브라우저 둘 다에서 도므로, 서버도 같은 채점 코드를 씁니다. `multi.js`의 방장 진행 부분(`hostTick`·`onHostMessage`)이 서버로 옮겨 갈 몫입니다.
